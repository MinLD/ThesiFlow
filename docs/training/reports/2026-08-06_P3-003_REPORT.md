## Contract Evidence

- `POST /organizations/:organizationId/invitations` returns pending invitation and normalized lowercase email.
- Response includes raw `invitationToken` only for delivery/test scope; database stores only `tokenHash`.
- Inviter must have active membership in the organization.
- `POST /membership-invitations/accept` requires active account whose email matches invitation email.
- Accept transaction marks invitation `accepted`, sets `acceptedAt`, creates active membership with `source=invitation`, sets `activatedAt`.
- Wrong account returns `403 MEMBERSHIP_INVITATION_RECIPIENT_MISMATCH`.
- Replay returns `409 MEMBERSHIP_INVITATION_NOT_PENDING`.
