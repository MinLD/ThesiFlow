# P3-004 Report — Tenant Context Switch APIs / Tests

## Summary

Implemented canonical tenant context switch API before any Phase 4 RBAC work. The endpoint is read-only, authenticates the caller through existing bearer JWT infrastructure, and resolves tenant context only from current database membership and organization state.

## API Contract

`POST /api/v1/tenant-context/switch`

Request DTO:

```json
{
  "organizationId": "uuid"
}
```

Response DTO:

```json
{
  "tenantContext": {
    "accountId": "uuid",
    "organizationId": "uuid",
    "membershipId": "uuid",
    "organization": {
      "id": "uuid",
      "name": "Organization name",
      "slug": "organization-slug"
    },
    "membership": {
      "id": "uuid",
      "status": "active",
      "source": "provisioning"
    }
  }
}
```

Error cases:

- `401 AUTH_REQUIRED` — missing/invalid bearer token or inactive account.
- `400 VALIDATION_ERROR` — missing/malformed `organizationId`.
- `403 MEMBERSHIP_INACTIVE` — no eligible tenant context, including non-member, inactive/invited membership, disabled/deleted organization.

## Authorization Rules

Switch requires all predicates in one DB lookup:

```text
authenticated active account
+
TenantMembership.accountId = account.id
+
TenantMembership.organizationId = request.organizationId
+
TenantMembership.status = active
+
Organization.status = active
+
Organization.deletedAt = null
```

The endpoint does not trust `tenantId`, `membershipId`, or `role` from client input.

## Security Notes

- Cross-tenant isolation enforced by `accountId + organizationId + active membership` DB query.
- Role forgery protected by not accepting role from client and not exposing any role field before Phase 4 role assignments exist.
- Organization information disclosure reduced by using `MEMBERSHIP_INACTIVE` for non-member, inactive membership, and unavailable organization.
- Token/session semantics unchanged: endpoint returns resolved context only; it does not issue a tenant-scoped JWT or persist active tenant in session. Future long-lived tenant context tokens need revocation analysis in Phase 4+.
