## 7. Findings

### Finding 1 — Accept transition chưa guard `pending` bên trong transaction

- Severity: P2 — SHOULD FIX
- Location: `apps/api/src/modules/organizations/organization.repository.ts:91`
- Requirement: Accept invitation phải replay-safe; task nhắc idempotency/race và unique membership guard.
- Hiện tượng: Transaction update invitation bằng `where: { id }`, không kèm điều kiện `status = pending`.
- Nguyên nhân: Service check `invitation.status !== "pending"` xảy ra trước transaction, không phải atomic guard.
- Rủi ro: Hai accept đồng thời có thể cùng qua pre-check; request thua có thể nhận `TENANT_MEMBERSHIP_ALREADY_EXISTS` thay vì replay/not-pending domain error.
- Hướng sửa: Developer tự đổi accept transaction sang `updateMany` guard `id + status=pending` hoặc re-read/lock trong transaction, sau đó map count `0` thành `MEMBERSHIP_INVITATION_NOT_PENDING`.
- Test kiểm chứng: Bổ sung future concurrency regression cho `membership-invitation-lifecycle.test.ts`.
