## 4. Prisma code

No new schema code. Existing contract required:

```prisma
model MembershipInvitation {
  id                 String                     @id @default(uuid())
  organizationId     String                     @map("organization_id")
  email              String
  tokenHash          String                     @unique @map("token_hash")
  status             MembershipInvitationStatus @default(pending)
  invitedByAccountId String                     @map("invited_by_account_id")
  expiresAt          DateTime                   @map("expires_at")
  acceptedAt         DateTime?                  @map("accepted_at")
  revokedAt          DateTime?                  @map("revoked_at")
  createdAt          DateTime                   @default(now()) @map("created_at")
  updatedAt          DateTime                   @updatedAt @map("updated_at")

  organization     Organization @relation(fields: [organizationId], references: [id], onDelete: Restrict, onUpdate: Cascade)
  invitedByAccount Account      @relation("MembershipInvitationInviter", fields: [invitedByAccountId], references: [id], onDelete: Restrict, onUpdate: Cascade)

  @@index([organizationId, status])
  @@index([email, status])
  @@index([expiresAt])
  @@map("membership_invitations")
}

model TenantMembership {
  id             String           @id @default(uuid())
  organizationId String           @map("organization_id")
  accountId      String           @map("account_id")
  status         MembershipStatus @default(invited)
  source         MembershipSource
  activatedAt    DateTime?        @map("activated_at")
  deactivatedAt  DateTime?        @map("deactivated_at")
  createdAt      DateTime         @default(now()) @map("created_at")
  updatedAt      DateTime         @updatedAt @map("updated_at")

  organization Organization @relation(fields: [organizationId], references: [id], onDelete: Restrict, onUpdate: Cascade)
  account      Account      @relation(fields: [accountId], references: [id], onDelete: Restrict, onUpdate: Cascade)

  @@unique([organizationId, accountId])
  @@index([accountId, status])
  @@index([organizationId, status])
  @@map("tenant_memberships")
}
```

Existing SQL partial index must remain:

```sql
CREATE UNIQUE INDEX "membership_invitations_pending_org_email_key"
ON "membership_invitations"("organization_id", "email")
WHERE "status" = 'pending';
```

## 5. Design rationale

- `email` is normalized lowercase before insert to make recipient matching deterministic.
- `tokenHash` stores only hash; raw token may be returned only as delivery material, never persisted.
- `status=pending` is required before accept; accepted/revoked/expired invitations cannot be replayed.
- Accept transaction must update invitation and create membership atomically.
- `@@unique([organizationId, accountId])` prevents duplicate membership on concurrent accept.
- Wrong account is rejected by comparing active account email to invitation email.
- Expired invitation should transition or behave as expired, not create membership.
